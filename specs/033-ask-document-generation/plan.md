# Implementation Plan: Ask-View Document Output

**Branch**: `033-ask-document-generation` | **Date**: 2026-11-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/033-ask-document-generation/spec.md`. Scope follows `.specify/assessments/doc-generation/decision.md`: the **library-derived tier only**; from-scratch/ungrounded generation is explicitly deferred and must not be added by this plan.

## Summary

Employees need a finished file, not only a chat answer. This feature lets an employee ask for a Word, Excel, PDF or plain-text document and receive a file whose content is the grounded answer already shown in the conversation, with the same citations and a readable sources appendix. The workstation renders the file from the **persisted** query row — never a second model generation — and returns the bytes; the desktop client asks for a format, opens the OS save dialog, and writes only to the employee's chosen path.

The server adds one authenticated endpoint, `POST /api/queries/{id}/documents`, and two additive wire fields (`queryId` on the answer response and the streamed answer event) so the client can reference the persisted answer from both live and history messages. A new `RAGGit.Documents` library owns detection, rendering and table shaping; DOCX/XLSX use the existing OpenXml SDK, PDF uses MIT-licensed SkiaSharp with an embedded Greek-capable font, and TXT is UTF-8. The client gains a per-message **Save as** action, automatic production when the question names exactly one supported format, a save service backed by `SaveFileDialog`, and no document libraries of its own. No schema change, no persistence of generated files, no library publication, no new runtime egress.

## Technical Context

**Language/Version**: C# / .NET 10 — libraries `RAGGit.Core`, `RAGGit.Ingest`, `RAGGit.Retrieval`, new `RAGGit.Documents`; ASP.NET Core host `RAGGit.Workstation.Api`; WPF-UI desktop `RAGGit.Client.WPF` + shared `RAGGit.Client.Core`.

**Primary Dependencies**:
- Existing: ASP.NET Core MVC, `System.Text.Json`, `DocumentFormat.OpenXml` 3.5.1 (already in `RAGGit.Ingest`), `PdfPig` 0.1.16 (tests read-back), `CommunityToolkit.Mvvm` 8.2.2, WPF-UI 4.3.0.
- New: `SkiaSharp` 4.156.1 (MIT) with its Win32/Linux native assets, plus an embedded `DejaVuSans` regular/bold font asset in `RAGGit.Documents`. No new client dependency — the desktop remains UI + `HttpClient`.

**Storage**: Unchanged. Documents are rendered from the existing `Queries`, `Chunks` and `Documents` rows through `IQueryRepository.GetDetailAsync`; generated bytes exist only in the HTTP response and the employee's saved file. No new table, column, file store or cache.

**Testing**: xUnit unit/contract/integration plus the WPF client screen tests. Unit: format detection, filenames, table shaping, citation mapping, DOCX/XLSX/PDF/TXT renderers, QueryViewModel and QueryDetailViewModel save lifecycle. Contract: endpoint auth/ownership/format/content type/filename, `422` eligibility, `404` cross-user, additive `queryId`. Integration: ask → render → read the file back with OpenXml/PdfPig, Greek text, typed spreadsheet cells, refusal, no persistence, offline subset. Client: every screen and the new XAML/bindings/WPF-UI traps. `dotnet csharpier check .` covers C# and XAML.

**Target Platform**: Windows workstation (API; the server filter also builds on Linux) + Windows desktop client; single-tenant, LAN/private-network only, offline at query time.

**Performance Goals**: Document rendering is CPU-only and never invokes the model. Typical reports render in under 2 s p95 on the constitution's hardware baseline; workstation-side document production (excluding the human save dialog) stays within 033 SC-006 (≤15% longer than the text-only answer). Rendering is capped at 25 MiB / 5 000 table rows; exceeding either returns `422` rather than producing an unusable file.

**Constraints**: Offline invariant untouched (packages are restored at build, not at query time). Citation-grounding unchanged: the document contains the persisted grounded answer; `no relevant content found` produces no file; zero-citation answers are not document-eligible. Per-user isolation inherited from `GetDetailAsync(sub, id)` — never `403`, always `404` for another user's query. No generated file reaches the shared library, the content store or LanceDB. The desktop must not carry OpenXml/PDF libraries. Greek labels and text are required. One document per request; no editing, templates, branding, batch or mail merge.

**Scale/Scope**: One new endpoint, one new library, one new client service, one Ask-surface save action, two additive wire fields. No new configuration keys, no schema migration, no background service, no new AI work. The assessed from-scratch tier is out of scope.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **I. Single-Tenant On-Prem or Private Cloud**: PASS — no tenant concept or `company_id`; the endpoint resolves the caller's `sub` and only the caller's own query. No cross-company or cross-user access.
- **II. Workstation-Owned AI**: PASS — all retrieval/generation stays on the workstation; document rendering is also workstation-side. The client only sends a format, shows the file dialog and writes bytes; no model, no document library, no AI work moves to the desktop.
- **III. .NET Library-First & Client Reuse**: PASS — detection/wire types live in `RAGGit.Core`; rendering lives in the new `RAGGit.Documents` library, independently unit-testable and reused by the API; the client reuses the shared types and adds no duplicate format logic.
- **IV. Offline Invariant (NON-NEGOTIABLE)**: PASS — no query-time egress. New packages/fonts are build-time assets; the renderer runs locally; the WAN-disabled offline suite is unchanged and must stay green.
- **V. Citation-Grounded RAG**: PASS — the document is a projection of the persisted grounded answer; citations are mapped to a sources appendix; the refusal string produces no file; a citationless answer is ineligible. No second generation, no hallucination surface.
- **VI. Test-First (NON-NEGOTIABLE)**: PASS — tests precede implementation at phase granularity; renderers are proved by reading the produced files back; contract tests cover ownership and error shapes; the offline gate is unaffected; the client screen tests catch XAML/binding regressions.
- **VII. Simplicity & Proprietary Stewardship**: PASS with justified additions — one new focused library (recorded in Complexity Tracking), one MIT PDF dependency and one embedded font, one client save service. No new state, no schema change, no background service, no speculative extension points.

**Pre-Phase-0 gate**: PASS. No violation requires rejection; the new project and PDF dependency are justified in Complexity Tracking.

**Post-Phase-1 re-check**: PASS — [research.md](research.md), [data-model.md](data-model.md) and [contracts/](contracts/) confirm the design is a read-only projection of persisted data, adds no schema/config/runtime egress, keeps the client free of document libraries, and preserves every citation and refusal rule. No new violation appears after design.

**Structure Decision**: The existing multi-project layout is retained. A new `RAGGit.Documents` library is the smallest coherent home for format rendering: it keeps OpenXml/SkiaSharp out of the client and out of the query library, and it is independently testable. The API keeps transport, ownership and persistence; `RAGGit.Core` keeps the wire types and the shared detector so client and server cannot drift. No new project is created for detection or the client seam.

Build integration: add `src/RAGGit.Documents/RAGGit.Documents.csproj` to `RAGGit.sln` and to the `RAGGit.Server.slnf` project list (Linux CI builds the filter), and add a project reference from `tests/unit` and `tests/contract` to `RAGGit.Documents` so renderer tests can read the produced files back.

## Complexity Tracking

| Addition | Why Needed | Simpler Alternative Rejected Because |
|----------|------------|--------------------------------------|
| New `RAGGit.Documents` project | Four format renderers, table shaping and citation mapping need an independently testable home. | Putting them in `RAGGit.Retrieval` couples query orchestration to word-processing/PDF libraries; putting them in the API violates library-first and cannot be unit-tested cleanly; putting them in `RAGGit.Ingest` mixes generation with read-only extraction. |
| `SkiaSharp` 4.156.1 + embedded DejaVu font | FR-001 requires PDF output; `PdfPig` is read-only. SkiaSharp is MIT, has no revenue-gated licence, and supports the embedded Greek font on Windows and Linux. | PDFsharp/MigraDoc 6.5 is AGPL or paid-commercial; PDFsharpCore drags a vulnerable ImageSharp line; QuestPDF is revenue-gated; iText is AGPL/commercial; system fonts are not guaranteed in Linux containers; dropping PDF violates the spec. |
| Additive `queryId` on `QueryResponse` / stream answer event | The save endpoint must reference the persisted answer without re-querying; the client needs the id on live and history messages. | A new column is unnecessary (the id exists); a server-side cache adds state and expiry; re-querying on save violates FR-003. |
| `IFileSaveService` in `Client.Core` | FR-012/013 require an OS save dialog and a user-chosen path; the existing launcher writes to temp. | Reusing `ILauncherService` conflates preview with save, cannot choose a location and would leave generated files behind; saving server-side violates FR-014 and loses the employee's chosen path. |
