# Implementation Plan: Application Icon

**Branch**: `024-client-app-icon` | **Date**: 2026-09-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/024-client-app-icon/spec.md`

## Summary

Give the desktop client a real application identity. The product currently declares no icon at all: no
asset exists in the repository, the client project sets none, and the shell therefore shows the generic
placeholder in the taskbar, in Alt-Tab and in the file system.

The approach is one committed multi-size icon asset, generated by a committed script so the mark is
reproducible without a design tool, plus its application to the three surfaces the client controls: the
executable's own icon (file system, taskbar, pinned), the window icon (Alt-Tab and taskbar grouping), and
the shell's custom title bar, which is a library control and does not draw the operating system's icon.
The mark is a simplified product silhouette on a filled tile in one **fixed** brand colour — the decision
recorded as FR-008 — so it stays legible on light and dark shells without following the user's Windows
accent, and the identity never depends on colour alone.

## Technical Context

**Language/Version**: C# / XAML, .NET 10 (`net10.0-windows10.0.17763.0`)

**Primary Dependencies**: WPF-UI `4.3.0` (already referenced — no new package). Verified for this
feature: `Wpf.Ui.Controls.TitleBar.Icon` is an `Wpf.Ui.Controls.IconElement` (so the shell's custom title
bar takes a nested icon element, not a string attribute), and `Wpf.Ui.Controls.FluentWindow` derives from
`System.Windows.Window` and exposes `Icon : System.Windows.Media.ImageSource`.

**Storage**: N/A — one committed asset plus the script that generates it; nothing at runtime.

**Testing**: `dotnet build RAGGit.sln -c Release -p:Platform=x64`; `dotnet csharpier check .`; the
existing Unit/Contract/offline suites unchanged; the static icon audits and the asset/screenshot review
in [quickstart.md](quickstart.md).

**Target Platform**: Windows 10 1809+ / Windows 11 desktop (unpackaged, self-contained build)

**Project Type**: Desktop application (WPF client)

**Performance Goals**: No measurable regression — the asset is loaded once when the shell starts.

**Constraints**: No new project, package, or service; no network access at build or run time; the mark's
colour is fixed and is not the operating system accent; no behaviour, automation-ID, or window-title
change; the mark must stay identifiable at the shell's smallest size and on both light and dark shells.

**Scale/Scope**: One asset (8 size variants: 16/20/24/32/40/48/64/256) plus its generator; touch-points
are the client project file, the shell window, the new asset folder, and this feature's documents.

**Structure Decision**: Keep the single-solution layout and the client-presentation scope. The mark lives
with the client that ships it (`src/RAGGit.Client.WPF/Assets/`), and the generator sits beside the asset so
the geometry, the colour, and the frame set are reproducible from the repository alone — no design tool,
no network, no new project. The only non-client documentation touch-point is a recording of the fixed
brand colour where the design system already documents colour roles.
