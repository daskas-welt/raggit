# Quickstart: Description-Based Document Creation

**Feature**: `034-prompted-document-creation`

## Prerequisites

- Windows workstation with the RAGGit API and configured local model running.
- Windows desktop client built from this checkout and a signed-in Employee or Admin account.
- For source-backed checks, at least one uploaded document must have settled to `Ready`; use the existing settled-status test helper rather than a fixed delay.
- The feature must work with WAN disabled; no internet service is a runtime dependency.

## Build and automated checks

From the repository root:

```powershell
dotnet tool restore
dotnet build RAGGit.Server.slnf -c Release
dotnet test tests/unit/RAGGit.Tests.Unit.csproj -c Release
dotnet test tests/contract/RAGGit.Tests.Contract.csproj -c Release
dotnet test tests/integration/RAGGit.Tests.Integration.csproj -c Release --filter "FullyQualifiedName~QueryOfflineTests|FullyQualifiedName~OfflineIdentityTests|FullyQualifiedName~OfflineHistoryTests|FullyQualifiedName~CrossUserIsolationTests"
dotnet test tests/client/RAGGit.Tests.Client.csproj -c Release
dotnet csharpier check .
```

The client test is Windows-only. The full solution build is also available on Windows with `dotnet build RAGGit.sln -c Release -p:Platform=x64`.

## End-to-end scenarios

1. Open **Create Document**, enter a self-contained description, choose each of TXT/PDF/DOCX/XLSX, create and save each result, and open it in the corresponding standard application. Confirm the file has the selected extension and usable content.
2. Request a deliverable explicitly based on a known uploaded document. Confirm the file includes relevant supported facts and identifies its source documents.
3. Request a standalone welcome note or similar content that has no relevant library material. Confirm the file clearly says no RAGGit sources were used and does not claim library verification.
4. With records for two people that share a template, request a document about one person. Confirm no facts from the other person's record appear.
5. Cancel the save dialog and cancel an in-flight generation. Confirm no file exists at an unchosen path and no generated document appears in Ask history, My Documents, or the shared library.
6. Repeat with WAN unavailable and the workstation model available. Confirm generation succeeds without external services. Then make the local model unavailable and confirm a safe error with no file.

## Expected result

- API response is a format-correct file with an OS-safe `Content-Disposition` filename.
- The client writes only to the location selected in the save dialog.
- Source-backed statements have valid citations and source entries; source-free output is labelled.
- No prompt, generated bytes, query-history row, or library document is retained by the workstation.
