# Feature Specification: RAGGit Offline-Mode Single-Tenant RAG Library

**Feature Branch**: `001-offline-mode`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "single-tenant RAG library for RAGGit: AI Workstation hosts Ollama and Qdrant local path with ASP.NET Core API; .NET client app (desktop + mobile) for admins to upload see library and employees to query with citations; LAN-only no cloud egress single-tenant proprietary" — Clarified 2026-09-10: client tier = Windows 11 modern desktop + iOS/Android mobile, no Linux (macOS not in scope); single .NET MAUI codebase selected at plan level.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Admin Uploads and Indexes Content (Priority: P1)

A company admin (RAGGit administrator) uploads documents to the single company library via the desktop app. The system chunks, embeds locally on the AI Workstation, and indexes into the single-tenant RAG store, making content searchable within minutes over LAN.

**Why this priority**: Without indexed content there is no value; this is the ingestion half of the MVP closed loop. Deliverable without query already validates ingestion pipeline.

**Independent Test**: Launch AI Workstation + desktop app on LAN. Admin logs in as Admin role, uploads 10 PDFs (50 pages each). Verify library list shows 10 documents with status Ready and vector count >0 via `GET /api/documents`, and a direct keyword semantic query returns hits. Can be tested without User Story 2 by checking search index directly.

**Acceptance Scenarios**:

1. **Given** admin is authenticated with Admin role and AI Workstation is reachable on LAN, **When** admin uploads a supported file (<100MB) via desktop app, **Then** file appears in library with status Indexing → Ready within 5 minutes for 50 pages and is retrievable via semantic search.
2. **Given** admin uploads an unsupported file type, **When** submission completes, **Then** system rejects with actionable error ("unsupported type: .exe") and no partial index is created nor library corrupted.

---

### User Story 2 - Employee Queries Library Offline with Citations (Priority: P1)

A company employee opens the desktop app, types a natural-language question, and receives a grounded answer generated by the local AI model on the AI Workstation, with citations to source documents. The entire flow works with WAN (internet) disabled — only LAN between desktop and workstation is required.

**Why this priority**: This is the user-visible value; together with US-1 it forms the viable MVP. Must prove Offline Invariant (Constitution IV).

**Independent Test**: Pre-seed library with known docs (seed script). Disconnect WAN on workstation (keep LAN), keep desktop connected to workstation. Employee (Employee role) asks “what is refund policy?” → verify 200 response contains `answer` + ≥1 citation (`documentId`/`chunkId`) and completes in <7s end-to-end (retrieval <2s + generation <5s on reference workstation). Test with no WAN.

**Acceptance Scenarios**:

1. **Given** library contains relevant content and WAN is disabled on workstation, **When** employee submits a natural query, **Then** system returns a generated answer with ≥1 citation to source chunks within 7 seconds and never calls an external cloud API.
2. **Given** query has no relevant content in the library, **When** employee submits it, **Then** system returns `no relevant content found` with zero citations and does NOT hallucinate an answer.

---

### User Story 3 - Admin Manages Library (Priority: P2)

Admin browses, previews, and deletes documents in the single-tenant library. Deletion purges vectors and metadata so subsequent queries no longer return deleted content. All employees immediately see the updated library.

**Why this priority**: Required for lifecycle but not for first demo; can be added after US-1/US-2 loop works.

**Independent Test**: Admin deletes one of the 10 documents from US-1, then employee queries a term unique to that deleted doc → 0 hits and citation absent.

**Acceptance Scenarios**:

1. **Given** library has N documents, **When** admin deletes a document, **Then** document is removed from `GET /api/documents`, its vectors are purged from the RAG store, and subsequent queries no longer cite it.

---

### User Story 4 - Employee Browses Library (Priority: P3)

Employee views the library (read-only) to discover available documents and understand coverage before querying.

**Why this priority**: Enhances discovery; deferrable.

**Independent Test**: Employee role can `GET /api/documents` and see same list as admin, but `POST /api/documents` and `DELETE` return 403.

**Acceptance Scenarios**:

1. **Given** employee is authenticated as Employee role, **When** they open the library view, **Then** they see the full document list (filename, size, status, createdAt) but upload/delete actions are disabled/hidden.

---

### Edge Cases

- Large file (>100MB or >10k pages) or batch of 50 concurrent uploads → system queues, shows progress, handles partial failure without corrupting existing index.
- Duplicate upload (same hash as existing doc) → system detects duplicate, returns existing documentId and does not re-index.
- AI Workstation AI unavailable (Ollama/LLM or vector DB down) → desktop shows `AI workstation unavailable` and query fails fast; upload is queued or rejected with retry.
- First-run air-gapped (no internet to fetch models) → workstation must have models pre-cached/bundled; otherwise startup fails with `model unavailable offline` (Constitution IV).
- Unsupported file or corrupted PDF → reject per US-1 scenario 2, log error, keep library consistent.
- LAN partition between desktop and workstation → desktop shows `cannot reach AI workstation` with retry, no cloud fallback.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow users with Admin role to upload documents to the single-tenant company library and list/delete them; users with Employee role MUST be able to list/view library read-only.
- **FR-002**: System MUST chunk, embed locally, and index uploaded content into the single-tenant embedded RAG store on the AI Workstation with no external vector service and no outbound cloud calls during ingest.
- **FR-003**: System MUST enforce role-based access: Admin can upload/delete, Employee can query/browse; unauthenticated requests MUST be rejected. No multi-tenant partitioning is required (single-tenant per deployment).
- **FR-004**: System MUST provide a natural-language query over the library that retrieves top-k relevant chunks and generates a grounded answer using the local AI model on the AI Workstation with zero outbound WAN at query time (LAN-only). The client app (desktop or mobile) MUST work as a thin client over LAN with no local models.
- **FR-005**: System MUST return citations (source documentId/chunkId/text) for every generated answer when source exists, and MUST return `no relevant content found` when no relevant chunks are found (no hallucination).
- **FR-006**: System MUST reject unsupported types/sizes with an actionable error and leave the existing library and index consistent (no partial writes).
- **FR-007**: System MUST handle AI model unavailability offline by failing fast with a clear `model unavailable offline` or `AI workstation unavailable` error, not hanging.
- **FR-008**: System MUST persist the RAG store and document metadata on the AI Workstation to disk and survive workstation restart; desktop is stateless.
- **FR-009**: System MUST operate on-prem over LAN/VPN as a proprietary single-tenant deployment; proprietary artifacts MUST be signed and distributed privately per company.

*Unclear aspects (max 3 markers):*

- **FR-010**: System MUST support upload formats PDF, docx, txt, and md only for v1; video/audio transcripts are out of scope for v1.
- **FR-011**: System MUST meet scale target of 5k documents / ~1M chunks per library maximum with chunk size 512 tokens / 50 overlap and retrieval topK=5 for v1.

### Key Entities *(include if feature involves data)*

- **Library**: Singleton per deployment representing the single company's content collection; attributes: id (singleton=1), name, createdAt.
- **Document**: File uploaded to library; attributes: id, filename, mime, size, hash (for dedupe), status (Indexing|Ready|Failed), createdBy, createdAt. Related to Library (1:N) and Chunk (1:N).
- **Chunk**: Text segment derived from a Document; attributes: id, documentId, ordinal, text, tokenCount. Source for embeddings.
- **Embedding**: Vector representation of a Chunk stored in RAG store; attributes: chunkId, vector (dim 384/768), modelName, payload {documentId, text}. Not a separate table in app DB if vector store owns it.
- **Query**: Employee natural-language request and response; attributes: id, userId, prompt, retrievedChunkIds, answer, citationIds, latencyMs, createdAt.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Admin uploads a 50-page PDF and it becomes searchable (status Ready) within 5 minutes on the reference AI Workstation (measured).
- **SC-002**: With WAN disabled on the workstation (LAN still connected), an employee query succeeds end-to-end with p95 <7 seconds (retrieval <2s + generation <5s) over 50 trials on reference workstation.
- **SC-003**: Retrieval precision: for a curated eval set of 50 Q/A pairs from the seeded library, top-5 results contain a relevant document for ≥80% of queries.
- **SC-004**: Citation coverage: 100% of answers that have a source include ≥1 citation; 100% of queries with no relevant source return `no relevant content found` (0% hallucination) on eval set.
- **SC-005**: Employee can view the full document list and query successfully, but upload/delete attempts return 403 (role enforcement) — verified for both roles.

## Assumptions

- Single-tenant per deployment; each company runs its own AI Workstation(s) + desktops on the same LAN/VPN — no shared cloud tenancy.
- Reference AI Workstation: 16GB RAM + GPU recommended, 10GB disk for models+DB; Client (desktop + mobile): 4GB RAM thin client, no local models (Constitution II). If hardware is lower, quantized small models (bge-micro-v2 80MB, phi-3-mini int4) will be used.
- Supported formats for v1: PDF, docx, txt, md only; video/audio transcripts out of scope.
- Chunking 512 tokens / 50 overlap, embedding dim 384 or 768, topK=5 — tunable via config, not per-user in v1.
- Authentication for v1: API key or Windows AD integrated on workstation; full SSO deferred. Upload rejects >100MB per file.
- AI Workstation hosts Ollama (embed + chat) and Qdrant local file (`QdrantClient(path=)`) or equivalent embedded vector store; client apps (desktop + mobile) connect via `https://ai-workstation.local:5001` over LAN (mobile requires same subnet or site VPN).
- Air-gapped first run requires pre-cached models; otherwise startup error is acceptable per FR-007.
- Proprietary distribution: signed MSIX (Windows 11) + private mobile distribution (iOS enterprise/Ad-Hoc, Android sideload) per company, private update channel. No public app-store listing required.
- Client platforms for v1: Windows 11 desktop + iOS/Android mobile from one codebase; mobile exposes same browse/upload/query flows as desktop — no mobile-only features (camera, push, biometrics) in v1.
